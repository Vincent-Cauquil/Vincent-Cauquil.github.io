Architecture : GUI + Headless via profils partagés

Architecture: GUI + Headless via shared profiles

Le besoin : piloter les 24 canaux du QDAC-II de façon interactive pour le réglage, mais aussi de façon scriptable et sans GUI pendant les mesures, quand un script de VNA doit garder le contrôle total du timing.

La solution : un gestionnaire de profils JSON partagé entre les deux modes.

  • Mode GUI (PySide6) : configuration par canal (mode, filtre passe-bas, gamme de courant, trigger), sauvegarde/chargement de profils.
  • Mode Headless : rechargement du même profil JSON, pilotage direct de l'instrument sans boucle d'événements graphique.
  • Découplage propre : ProfileManager n'a besoin que d'un objet exposant channel_configs — la MainWindow en GUI, un simple conteneur en headless.

The need: drive the 24 QDAC-II channels interactively for setup, but also in a scriptable, GUI-less way during measurements, when a VNA script must keep full control of timing.

The solution: a shared JSON profile manager used by both modes.

  • GUI mode (PySide6): per-channel configuration (mode, low-pass filter, current range, trigger), profile save/load.
  • Headless mode: reloads the same JSON profile and drives the instrument directly, with no GUI event loop.
  • Clean decoupling: ProfileManager only needs an object exposing channel_configs — the MainWindow in GUI, a small container in headless mode.

Driver SCPI bas niveau (PyVISA)

Low-level SCPI driver (PyVISA)

Deux couches : un wrapper Instrument (context manager PyVISA) et une couche instrument qdac_II.

  • Modes de sortie : DC fixe, List, Sweep, Sine/Square/Triangle, AWG, Datastream, Sensing.
  • AWG optimisé : mémoire de traces partagée (plusieurs canaux réutilisent une trace avec amplitude/offset propres), envoi des échantillons en bloc binaire pour la vitesse, gestion de la contrainte « nombre d'échantillons pair » et de la limite de 4×10⁶.
  • Interface Ethernet privilégiée à l'USB (1 Mbit/s) pour l'upload des traces.
  • Diagnostic intégré : batterie de requêtes SCPI (*IDN?, SYST:ERR?, relecture gammes/filtres…) avec rapport ✓/✗.

Two layers: an Instrument wrapper (PyVISA context manager) and a qdac_II instrument layer.

  • Output modes: Fixed DC, List, Sweep, Sine/Square/Triangle, AWG, Datastream, Sensing.
  • Optimized AWG: shared trace memory (several channels reuse one trace with their own amplitude/offset), samples sent as a binary block for speed, handling the "even sample count" constraint and the 4×10⁶ limit.
  • Ethernet interface preferred over USB (1 Mbit/s) for trace upload.
  • Built-in diagnostics: a battery of SCPI queries (*IDN?, SYST:ERR?, range/filter read-back…) with a ✓/✗ report.

Caractérisation circuit-ouvert & arrêt sécurisé

Open-circuit characterization & safe shutdown

Caractérisation : un utilitaire balaye une liste de tensions sur les 24 canaux (gamme de courant LOW), enregistre le courant, ajuste une droite et en déduit la résistance de fuite (1/pente) et le courant d'offset (ordonnée à l'origine) par canal.

Sécurité : séquence safe_shutdown() robuste — arrêt des générateurs, rampe à 0 V, passage en gammes basses, nettoyage des traces, *CLS. Chaque étape est protégée pour qu'un échec isolé ne bloque pas l'arrêt.

Characterization: a helper sweeps a voltage list over all 24 channels (LOW current range), records the current, fits a line and derives the per-channel leakage resistance (1/slope) and offset current (intercept).

Safety: a robust safe_shutdown() sequence — stop generators, ramp to 0 V, switch to low ranges, clear traces, *CLS. Each step is guarded so a single failure does not block the shutdown.
