Construction de l'Environnement (Le Pont Python-SPICE)

Building the Environment (The Python-SPICE Bridge)

La Démarche : Avant de faire de l'IA, il fallait "parler" au simulateur. J'ai créé un environnement custom compatible Gymnasium (StandardCellEnv) capable d'interagir avec NGSpice en boucle fermée.

Défis Techniques :

  • Génération dynamique de Netlists : Un CellModifier parse la netlist SPICE de référence, localise chaque transistor et réinjecte les largeurs W dictées par l'agent — sans passer par des templates .param figés.
  • Testbench auto-généré : Le système analyse la signature de la cellule (entrées/sorties) pour créer les stimuli PULSE et injecter les commandes .meas couvrant toutes les transitions logiques critiques.
  • Parsing robuste des fichiers .raw : Extraction automatique des métriques PPA (délais rise/fall, slew rates, énergie dynamique, puissance de fuite).
  • Optimisation critique : Le RL nécessitant des milliers de simulations, j'ai combiné SubprocVecEnv (parallélisation multi-cœurs) et un SimulationCache par hachage (W + VDD + Température) qui restitue en O(1) tout résultat déjà calculé.

The Approach: Before tackling AI, I needed to "talk" to the simulator. I built a custom Gymnasium-compatible environment (StandardCellEnv) interacting with NGSpice in a closed loop.

Technical Challenges:

  • Dynamic Netlist Generation: A CellModifier parses the reference SPICE netlist, locates each transistor and re-injects the W widths dictated by the agent — no frozen .param templates required.
  • Auto-generated Testbench: The system analyzes the cell signature (inputs/outputs) to create PULSE stimuli and inject the .meas commands covering every critical logic transition.
  • Robust .raw File Parsing: Automated extraction of PPA metrics (rise/fall delays, slew rates, dynamic energy, static leakage).
  • Critical Optimization: Since RL requires thousands of simulations, I combined SubprocVecEnv (multi-core parallelization) with a hash-based SimulationCache (W + VDD + Temperature) returning any already-computed result in O(1).

Reward Engineering : quand l'agent apprend à tricher

Reward Engineering: when the agent learns to cheat

L'Agent IA : PPO (Proximal Policy Optimization) via Stable-Baselines3, sur un espace d'actions continu. L'agent ne prédit pas des largeurs absolues mais un pourcentage de variation ∈ [-20 %, +20 %] appliqué aux dimensions courantes, ce qui stabilise nettement la convergence.

Le bug le plus instructif du projet : avec une pénalité de crash fixée à -10, l'agent a découvert qu'il était mathématiquement plus rentable de faire planter NGSpice (-10) que de tester une configuration valide mais éloignée des cibles (jusqu'à -60 avec la pénalité quadratique).

  • Symptôme : oscillations violentes, pics récurrents à -10, aucune convergence.
  • Diagnostic : cas d'école de reward hacking — l'agent exploitait une faille de la fonction de récompense, pas le problème physique.
  • Correctif : application de la règle « l'échec doit toujours être la pire situation possible » → pénalité abaissée à -100. La convergence est devenue immédiatement stable.

Fonction de reward (V1.2) : pénalité quadratique sur l'erreur relative, contrainte physique pénalisant les cas WPMOS < WNMOS (mobilité des trous), et bonus de +20 lorsque toutes les métriques entrent dans la tolérance.

AI Agent: PPO (Proximal Policy Optimization) via Stable-Baselines3, on a continuous action space. The agent doesn't predict absolute widths but a variation percentage ∈ [-20%, +20%] applied to current dimensions, which markedly stabilizes convergence.

The most instructive bug of the project: with a crash penalty set at -10, the agent discovered it was mathematically more profitable to crash NGSpice (-10) than to try a valid but off-target configuration (down to -60 with the quadratic penalty).

  • Symptom: violent oscillations, recurring spikes at -10, no convergence.
  • Diagnosis: textbook reward hacking — the agent was exploiting a flaw in the reward function, not solving the physical problem.
  • Fix: applying the rule "failure must always be the worst possible outcome" → penalty lowered to -100. Convergence became immediately stable.

Reward function (V1.2): quadratic penalty on relative error, physical constraint penalizing WPMOS < WNMOS cases (hole mobility), and a +20 bonus when all metrics fall within tolerance.

📊 Résultats & Perspectives

📊 Results & Perspectives

Performance obtenue : l'agent dimensionne avec succès les 20 transistors d'une XOR2 Sky130 pour approcher des cibles PPA imposées. Sur l'exemple ci-contre, le Delay Rise passe de 132,8 ps (référence) à 101,0 ps pour une cible de 120,8 ps — la contrainte de délai est dépassée, au prix d'une surface légèrement au-dessus de la cible (2,63 µm² vs 2,00 µm²).

Séparation Training / Inférence : pendant l'entraînement, l'environnement génère des cibles aléatoires à chaque reset pour forcer l'exploration de tout l'espace de conception. En inférence, le mode mode="inference" désactive ce tirage et impose les objectifs saisis par l'utilisateur.

Limites identifiées :

  • Optimisation multicritère : les objectifs Délai / Puissance / Surface sont antagonistes. L'agent privilégie les métriques les plus fortement pondérées et n'atteint pas systématiquement toutes les cibles simultanément.
  • Généralisation : un modèle entraîné sur une cellule se transfère mal à une topologie différente ; chaque cellule requiert son propre apprentissage.
  • Pas de reprise d'entraînement : impossible actuellement de recharger un modèle pour poursuivre son fine-tuning — chaque session repart de zéro.
  • Coût SPICE : malgré le cache et la parallélisation, la simulation transistor-level reste le goulot d'étranglement.

Pistes d'amélioration :

  • Remplacer NGSpice par des modèles de substitution (Surrogate Models) — régression ou réseau de neurones entraîné sur les points déjà simulés.
  • Implémenter le chargement de modèle pré-entraîné pour capitaliser l'expérience entre sessions.
  • Explorer SAC (Soft Actor-Critic), mieux adapté aux espaces continus et plus économe en échantillons que PPO.

Performance achieved: the agent successfully sizes the 20 transistors of a Sky130 XOR2 to approach imposed PPA targets. In the example shown, Delay Rise drops from 132.8 ps (reference) to 101.0 ps against a 120.8 ps target — the timing constraint is exceeded, at the cost of a slightly oversized area (2.63 µm² vs 2.00 µm²).

Training / Inference separation: during training, the environment generates random targets at every reset to force exploration of the whole design space. At inference time, mode="inference" disables this sampling and enforces the user-defined objectives.

Identified limitations:

  • Multi-objective optimization: Delay / Power / Area targets are antagonistic. The agent favors the most heavily weighted metrics and doesn't systematically hit all targets at once.
  • Generalization: a model trained on one cell transfers poorly to a different topology; each cell requires its own training run.
  • No training resumption: currently impossible to reload a model for further fine-tuning — every session starts from scratch.
  • SPICE cost: despite caching and parallelization, transistor-level simulation remains the bottleneck.

Improvement paths:

  • Replace NGSpice with Surrogate Models — regression or a neural network trained on already-simulated points.
  • Implement pre-trained model loading to accumulate experience across sessions.
  • Explore SAC (Soft Actor-Critic), better suited to continuous spaces and more sample-efficient than PPO.
